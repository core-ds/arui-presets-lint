# Добавление правил дизайн-системы

Правила используют стандартный интерфейс ESLint `RuleModule`. Каждое правило находится
в отдельном файле и содержит свою схему настроек, сообщения и обработчики AST.

- `rules/` — реализации правил. За образец правила с реестром можно взять
  `rules/no-deprecated-props.ts`, а проверки аннотаций TypeScript —
  `rules/no-deprecated-components.ts`.
- `utils.ts` — общие функции для определения импорта и JSX-компонента, построения схем
  и сообщений. Они учитывают алиасы импортов, составные компоненты и локальное затенение.
- `types.ts` — типы настроек и `DesignSystemOptions` для фабрики конфигурации.
- `plugin.ts` — регистрация правил в плагине.
- `config.ts` — фабрика `createDesignSystemConfig`: области файлов и настройки правил.
- `index.ts` — публичные экспорты плагина, фабрики и типа настроек.

## Новое правило

1. Создайте файл в `rules/` и экспортируйте `RuleModule`. Настройки и состояние проверки
   храните в `create(context)`, чтобы они относились только к текущему файлу.
   Общие функции из `utils.ts` используйте там, где они подходят для проверки.
2. Добавьте правило в `designSystemPlugin.rules` в `plugin.ts`. После регистрации его
   можно настраивать обычной записью `design-system/имя-правила` в ESLint-конфигурации.
3. Если правило должно подключаться фабрикой, добавьте его в `createDesignSystemConfig`
   в `config.ts`.
   Выберите область файлов: JS/TS, JSX/TSX или только TSX для проверки с типами.
   Если нужны новые параметры фабрики, добавьте их в `DesignSystemOptions` в `types.ts`.
4. Для правила с реестром возвращайте `{}` из `create(context)` при пустом реестре,
   чтобы не регистрировать обработчики AST. Для правил с типовой информацией используйте
   TypeScript checker из `context.sourceCode.parserServices` проверяемого проекта.
5. Добавьте тесты на реальных фрагментах кода. Для проверок синтаксиса используйте
   `createRuleTester` из `eslint-vitest-rule-tester`, как в
   `test/rules/design-system.test.ts`. Проверки JSDoc, перегрузок и реэкспортов добавляйте
   в `test/rules/design-system-integration.test.ts` с настоящими TypeScript-декларациями.
   Проверьте нарушение, допустимый случай и настройки нового правила.
6. Опишите подключение и поведение в README пакета. Для изменения, которое попадет
   в релиз, добавьте changeset по правилам репозитория.

Из корня монорепозитория запустите полный набор проверок и сборку:

```sh
yarn test
yarn build
```
